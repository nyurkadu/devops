# Lesson 5 Lab — Ansible Templates & Roles on Docker Desktop

Practice environment for the `lesson5.md` exercise: **one container, no Dockerfiles, no docker-compose, no SSH keys, no systemd.**

Both parts of the exercise run against `localhost`. The container only needs Ansible — there is a ready-made public image with it preinstalled.

---

## Step 1 — Start the container (PowerShell)

Make sure Docker Desktop is running, then:

```powershell
docker run -d --name lab geerlingguy/docker-ubuntu2204-ansible:latest sleep infinity
```

That image is Ubuntu 22.04 with Ansible already installed — nothing to build.

Check it is alive:

```powershell
docker exec lab ansible --version
```

You should see `ansible [core 2.17.x]`.

> **Do not add `--privileged --cgroupns=host` and boot `/lib/systemd/systemd`.** Systemd as PID 1 fails to start under Docker Desktop's WSL2 backend (the container exits 255 with no logs), and this lab does not need it — see the note in Step 5.

## Step 4 — Part 1: the Jinja2 template

Create the template:

```bash
mkdir -p templates
cat > templates/nginx_load_balancer.conf.j2 << 'EOF'
# Generated by Ansible on {{ ansible_date_time.iso8601 }}
# Target Environment: {{ env | default('development') }}

upstream backend_nodes {
{% for host in groups['webservers'] %}
    # Server Node: {{ host }}
    server {{ hostvars[host]['ansible_host'] | default(host) }}:80 max_fails=3 fail_timeout=30s;
{% endfor %}
}

server {
    listen 80;
    server_name {{ domain_name | default('localhost') }};

    location / {
        proxy_pass http://backend_nodes;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF
```

Now the playbook.

> **Note:** in the original `lesson5.md` this `cat` block is missing its closing `EOF` (the stray one sits at the very bottom of the file). It is included correctly below.

```bash
cat > test_jinja_render.yml << 'EOF'
---
- name: Test Advanced Template Rendering
  hosts: localhost
  connection: local
  vars:
    domain_name: "app.example.com"
    env: "production"

  tasks:
    - name: Render dynamic template locally for inspection
      template:
        src: templates/nginx_load_balancer.conf.j2
        dest: /tmp/nginx_load_balancer.conf

    - name: Display rendered template
      command: cat /tmp/nginx_load_balancer.conf
      register: rendered_conf

    - name: Print output
      debug:
        var: rendered_conf.stdout_lines
EOF
```

Run it:

```bash
ansible-playbook -i inventory.ini test_jinja_render.yml
```

**What to look at:** the `{% for %}` loop expanded into a `server localhost:80 ...` line, read from the *inventory group*. Add a second line to `inventory.ini` (e.g. `web2 ansible_host=10.0.0.5`) and re-run — the upstream block grows without touching the template. That is the whole lesson of Part 1.

## Step 5 — Part 2: the role

Scaffold the role:

```bash
ansible-galaxy role init roles/webserver
```

### File 1 — `roles/webserver/defaults/main.yml`

```bash
cat > roles/webserver/defaults/main.yml << 'EOF'
---
webserver_port: 80
webserver_doc_root: /var/www/html
EOF
```

### File 2 — `roles/webserver/handlers/main.yml`

```bash
cat > roles/webserver/handlers/main.yml << 'EOF'
---
- name: restart webserver
  service:
    name: "{{ webserver_service_name }}"
    state: restarted
EOF
```

### File 3 — `roles/webserver/templates/index.html.j2`

```bash
cat > roles/webserver/templates/index.html.j2 << 'EOF'
<h1>Managed by Ansible Role: webserver</h1>
<p>Host: {{ ansible_hostname }}</p>
<p>IP: {{ ansible_default_ipv4.address | default('N/A') }}</p>
EOF
```

### File 4 — `roles/webserver/tasks/main.yml`

```bash
cat > roles/webserver/tasks/main.yml << 'EOF'
---
- name: Set OS-specific package name
  set_fact:
    webserver_service_name: "{{ 'apache2' if ansible_facts['os_family'] == 'Debian' else 'httpd' }}"

- name: Update package cache (Debian)
  apt:
    update_cache: yes
  when: ansible_facts['os_family'] == 'Debian'

- name: Update package cache (RedHat)
  dnf:
    update_cache: yes
  when: ansible_facts['os_family'] == 'RedHat'

- name: Install webserver package
  package:
    name: "{{ webserver_service_name }}"
    state: present

- name: Ensure document root directory exists
  file:
    path: "{{ webserver_doc_root }}"
    state: directory
    mode: '0755'

- name: Deploy index.html template
  template:
    src: index.html.j2
    dest: "{{ webserver_doc_root }}/index.html"
  notify: restart webserver

- name: Ensure webserver service is started and enabled
  service:
    name: "{{ webserver_service_name }}"
    state: started
    enabled: true
EOF
```

### File 5 — `site.yml` (calls the role)

```bash
cat > site.yml << 'EOF'
---
- name: Apply Webserver Role to Web Nodes
  hosts: webservers
  become: true

  roles:
    - role: webserver
      vars:
        webserver_port: 8080
EOF
```

Run it:

```bash
ansible-playbook -i inventory.ini site.yml
```

The Apache install takes a minute on the first run.

> **Why this works without systemd:** the last task uses the `service` module, which is a wrapper — with no systemd present it falls back to the SysV init script that the `apache2` package ships (`/etc/init.d/apache2`). Both `state: started` and `enabled: true` succeed. Verified on this image.

## Step 6 — Check it worked

```bash
curl http://localhost
```

You should get the HTML with your hostname and IP.

Then run the playbook a **second time**:

```bash
ansible-playbook -i inventory.ini site.yml
```

`changed=0`, and the handler does **not** fire. That is idempotency — the point of Part 2.

Now edit `roles/webserver/templates/index.html.j2`, run again, and watch `restart webserver` fire exactly once at the end of the play.

## Step 7 — Clean up

Type `exit` to leave the container, then in PowerShell:

```powershell
docker rm -f lab
```

> Files live inside the container and vanish with it. To keep them on Windows, add `-v ${PWD}\project:/project` to the `docker run` in Step 1 — but then create and edit files **inside** the container only, or Windows CRLF line endings will break the YAML.

---

## Two notes on the exercise itself

- **`webserver_port: 8080` is never used.** `site.yml` passes it in, but no task or template reads it, so Apache stays on port 80 — that is why `curl http://localhost` works. Making the port actually apply is a natural bonus task.
- **The `os_family` branch only exercises one side here.** On Ubuntu you always get `apache2`. Hitting the `httpd` branch would need a RedHat-family host — not required to complete the exercise.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| `container ... is not running` right after Step 1 | You booted systemd (`/lib/systemd/systemd`) instead of `sleep infinity`. It exits 255 under Docker Desktop. Run `docker rm -f lab` and redo Step 1 exactly as written. |
| `docker: invalid reference format` | Line-continuation problem in PowerShell. Keep the whole `docker run` on one line. |
| YAML error about `\r` or tabs | The file was created on Windows with CRLF. Create files inside the container, or run `sed -i 's/\r$//' file.yml`. |
| Apache install hangs | No internet in the container. Test with `curl -I https://archive.ubuntu.com` and check Docker Desktop network settings. |
| `ansible-galaxy: command not found` | Ansible is not installed — you are on the fallback image. Run `apt-get update && apt-get install -y ansible`. |
| Warning about discovered Python interpreter | Harmless. Silence it by adding `ansible_python_interpreter=/usr/bin/python3` to the host line in `inventory.ini`. |
